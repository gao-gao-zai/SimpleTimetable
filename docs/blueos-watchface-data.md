## 数据和有效期

已保存且启用的档案由 App 解析成今日只读摘要：当前课、下一节、教师、时间轴、版本、真实更新时间、有效期和设备时差。数据通过同签名 vendor exchange 发布，公共事件仅提示重读。消费者不读取完整档案，也不依赖手机保持连接。接口声明使用 Toolkit 对应的 `system.storage`、`service.exchange`、`system.event`。

消费者先显示自身本地缓存，再读取 exchange；成功的新摘要写入缓存。exchange 重启不持久；消费者缓存可保留，但不延长有效期。摘要最多一小时，且不超过校正时间的跨日或下一临时规则边界。有效期和时钟回拨检查使用真实系统时间；时差只影响课程状态。+60 秒表示课程时间提前一分钟，不修改系统时钟。

每个标准卡实例有独立 reader、订阅和计时器，隐藏时停止，显示时恢复；关闭一个不会停止另一个。点击状态可刷新。App 首次课程数据提交后才排队生成摘要，保存结果先显示，再生成共享摘要。后台冻结、跨日和超过一小时后需重新打开 App 更新；没有长期离线跨日或后台持续刷新承诺。

## 使用和安装条件

1. 本地使用维护者原有合法签名编译 App 和表盘；同签名是 vendor 空间可互读的条件。现环境缺原签名，当前不能验证覆盖安装或共享链路。
2. 在 App 选择并显式启用档案；打开“现在”页发布摘要。
3. 可在“管理 → 高级与诊断 → 课程卡预览”查看普通页面，或在支持安装标准卡的路径安装独立卡包。
4. 卡片“已过期”时打开 App 更新；手机同步不是刷新摘要的前提。

普通 RPK、标准卡 RPKS 和普通预览页是不同交付物。历史中 OrbitV 2.2.7 不能安装 RPKS；普通 RPK 安装日志出现 `widgets/Now` 声明被剔除，侧滑没有卡。不能以安装主 App 成功或普通预览可见推断标准卡已登记，也不能据此断言 GT2 不支持所有第三方卡。

安装查询包含应用、实际卡片、不存在的空模块、普通页四项。负对照也返回 true 时显示“当前查询不能证明卡片已安装”；超时、接口不可用和未安装分别提示。没有使用未经证实的 OrbitV 入口或“终端输入 help”指引。
