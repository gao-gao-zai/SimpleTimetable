# SimpleTimetable 产品需求

- 基线日期：2026-10-11（Asia/Shanghai）
- 状态：需求访谈结果，尚未实现
- 范围：第一版产品要求，以及安卓优先、后续覆盖 BlueOS 的平台目标
- 关联文档：[验收计划](acceptance.md)、[决策与待核实事项](decisions-and-open-questions.md)

## 1. 产品目标与优先级

### REQ-001 产品定位

创建类似 ClassIsland 的课表工具，保留其科目、时间表、课表管理能力，重新设计呈现方式与 UI，以适应手机、小屏手表、Android 和 BlueOS。

主要使用场景：

1. 上课时主动打开显示页，查看当前课程和距下课时间。
2. 课间查看下一节课程及距上课时间。
3. 查看接下来的课程安排。
4. 在设备上维护科目、时间表和课程表。

安卓端优先可用。小屏安卓手表与普通手机都必须得到完整适配；手机界面不能只是手表界面的放大版本。具体布局在后续 UI 设计阶段确定。

### REQ-002 管理范围

以 ClassIsland 的科目、时间表、课表管理功能为对照基线，包含其高级管理规则，不能因“不需要复杂设置”而自行删减已要求的管理能力。

明确排除自动化行动与提醒配置。应用设置保持简洁，视觉自定义仅提供用户已要求的字号、主题色及主题模式等选项，不做自由布局编辑器。

## 2. 平台与设备

| ID | 平台 | 已知条件 | 适配要求 |
| --- | --- | --- | --- |
| REQ-010 | 普通安卓手机 | 具体型号及最低版本未确定 | 完整功能，仅竖屏；充分利用长屏空间 |
| REQ-011 | 非 Wear OS 安卓手表 | 杂牌设备，Android 11，分辨率约 410×502；有触屏、全面屏手势和虚拟键盘 | 完整编辑与查看；边角不便点击；不依赖实体键、旋钮或物理键盘 |
| REQ-012 | 1:1 方屏安卓设备 | 原始要求明确包含真正的 1:1 屏幕 | 与约 410×502 的矩形屏一起覆盖，不能把两者视为同一比例 |
| REQ-013 | vivo WATCH GT2 | BlueOS，具体系统版本待核实；无自由文字键盘，用户表示不能连接 Wi-Fi | 独立查看、选择预设科目、修改时间和规则、安排课程及临时调课；蓝牙导入安卓端数据 |

安卓手机及安卓手表的文字输入使用软键盘。GT2 的科目来自应用内置预设或安卓端编辑后传入的数据，不要求在 GT2 上输入自由文字。

GT2 可以独立修改上下课时间、轮换规则、课程安排和临时调课。没有手机连接时，已保存的数据仍可用于查看与上述编辑。涉及自定义名称的操作方式见待核实事项，不假定 GT2 有键盘。

## 3. 数据与课表管理

### REQ-020 基本对象及关系

采用 ClassIsland 的管理概念作为对照：

- **档案**：包含科目、时间表和课表等数据，支持管理和切换。
- **科目**：可被课程安排引用，包含全称、简称、教师、户外课程标记等 ClassIsland 基础字段；本项目还要求按学科区分颜色。
- **时间表**：定义上课、课间等时段和分割线，可被多个课表共用。
- **课表**：在时间表提供的课程时段中安排科目，并配置启用规则。
- **课表群**：按 ClassIsland 的逻辑组织和启用一组课表。

科目、时间表、课表的创建、编辑、复制、删除，以及多档案管理均纳入对照范围。删除引用对象时的具体保护行为、全部字段和边界规则须与参考项目进一步核对，不以此概要代替完整功能清单。

### REQ-021 规则及高级管理

用户要求以下范围参照 ClassIsland，后续应逐项核对文档及实现：

- 星期及多周轮换规则、周次基准与偏移。
- 多套作息、共享时间表、时段编辑、默认时长与默认科目。
- 课程与课间显示规则、空白时段与连堂安排的表示。
- 手动／自动启用、临时课表、临时层与课表群。
- 当日和跨天换课、永久换课、预定临时安排。
- 临时覆盖、启用优先级、有效期和失效后的回退规则。
- 时间段重叠、引用缺失、无匹配课表等边界行为。

不增加用户未要求的大学教务系统对接或任意日期规则；如果参考项目无法覆盖某类规则，应列出差异后讨论。

### REQ-022 运行状态与编辑分离

- “当前实际启用的课表”与“浏览、预览、编辑的课表”是不同状态。
- 查看其他日期或编辑其他课表不能自动切换当前实际启用课表。
- 点击保存后，修改立即进入实际数据；若影响当前运行课表，显示页立即重算。
- 手动启用、临时启用等仍属于独立操作。
- 自动保存、草稿等额外机制未被要求，不能替代明确的保存行为。

### REQ-023 共享时间表

按 ClassIsland 的引用关系处理：修改同一时间表影响所有引用它的课表；需要独立作息时，复制时间表并让目标课表改用该副本。

不把“每次修改都弹出修改共用／复制二选一”视为已确认要求。引用影响提示的具体 UI 后续设计。

### REQ-024 临时安排持久化

临时课表及临时调课必须跨应用进程重启保留，按配置的有效期失效。当天有效的安排到期后恢复正常规则。

应用退出、系统回收进程或重新打开应用，不能提前清除仍有效的临时安排。这是用户明确选择的移动端行为，优先于参考项目文档中的退出清除规则。

## 4. 查看、倒计时与进度

### REQ-030 显示状态

| 状态 | 主要内容 |
| --- | --- |
| 正在上课 | 当前课程、距下课时间、当前课程已过去的进度 |
| 课间且后续有课 | 下一节课程、距上课时间、课间已过去的进度 |
| 当天第一节课前 | 下一节课程及距上课时间；进度区间的起点待定义 |
| 两节课之间未显式录入课间 | 仍显示下一节及距上课时间，不要求用户必须补录课间才能查看 |
| 当日确实没有课程 | “今日无课” |
| 当日所有课程已结束 | 与“今日无课”区分，显示课程已结束状态 |

当前课程、距下课时间、下一节课程、距上课时间是信息优先级依据。首页的信息布局尚未定稿。

### REQ-031 倒计时与进度条

- 倒计时显示精确到秒。
- 上课与课间都需要进度条，表示**已经过去的比例**，不是剩余比例。
- 安卓应用、GT2 应用、安卓静默通知、安卓桌面小组件及 GT2 快捷卡片都必须显示进度条。
- 不能因外部入口刷新限制而直接取消进度条。
- 应用页面以可见时每秒更新为设计目标；不可见时停止页面秒级更新，重新显示时按当前时间立即重算。
- 外部入口的数字、进度条、课程状态切换是不同更新任务，实际刷新频率须分别验证；目前没有承诺所有入口的进度条均每秒更新。
- 未显式定义课间、第一节课前等场景的进度起点尚未确认，见待核实事项。

### REQ-032 浏览方式

提供以下三种浏览方式：

1. 一张卡片对应一节课的课程卡片。
2. 时间轴。
3. 周课表。

手表周课表按天分页，**每页一天**。手机周课表的具体布局、不同视图之间的切换方式及默认视图留到 UI 设计阶段。

### REQ-033 系统入口

- 普通安卓手机和安卓手表均需要桌面小组件与可关闭的静默常驻通知。
- vivo WATCH GT2 需要应用入口与快捷卡片，用户主动进入显示页。
- 不要求抬腕后强制顶替系统表盘，不做上下课主动提醒。
- 静默常驻通知承担信息展示，不发声音、振动或主动提醒弹窗。
- 安卓手表桌面对小组件的支持、GT2 快捷卡片接口开放情况仍待验证；目标不因“待验证”而视为已实现。
- 常驻通知默认开关状态尚未确定。

## 5. 视觉、操作与无障碍

### REQ-040 视觉要求

- 简洁彩色卡片风格。
- 颜色用于区分学科和当前状态。
- 支持浅色、深色与跟随系统模式。
- 提供字号与主题色调整，不做复杂主题或自由布局配置。
- 不做花哨动画。
- 小屏手表和普通长屏手机都需要合理排版，仅竖屏。

### REQ-041 文本及无障碍

- 支持大字号、高对比度、减少动画和读屏。
- 课程名过长时优先缩小字体；达到最低可读字号后允许换行，并可查看完整名称。
- 不为塞入完整名称而无限缩小文字。
- 关键操作不依赖难以点击的边角，也不依赖实体旋钮或物理键盘。
- 具体字号下限、触控区域尺寸、分页控件及手势在 UI 设计与实测中确定。

## 6. 时间来源与校时

### REQ-050 时间模式

允许选择系统时间或软件内部时间。软件时间允许自动联网校时，因此“离线”指核心课表功能不依赖网络，不代表禁止所有网络访问。

有效课表时间按以下概念计算：

> 所选时间来源 + 学校铃声偏移

支持按秒设置学校铃声提前／延后。设备自身时钟校准与学校铃声偏移分开管理，不把某台设备的校准误差直接复制到另一台设备。

### REQ-051 断网与恢复

- 软件校时后断网，继续依据最近一次有效校时推算，并显示校时状态。
- 重启后若无法可靠恢复软件时间，允许暂用系统时间并提示需要重新校时。
- 手动同步课表时可同步学校铃声偏移；设备自身校准值分别保留。
- GT2 不依赖 Wi-Fi；其软件时间如何经蓝牙或平台接口获得校准值需要技术验证。
- 自动联网校时间隔、默认时间模式与失败重试策略尚未确定。

## 7. 录入、导入和设备同步

### REQ-060 数据录入与导入

- 支持手动录入。
- 支持 ClassIsland 档案文件导入，未指定版本；实际支持的格式与版本须核对后记录。
- 支持 Excel／CSV 导入，具体处理方式要求参考 ClassIsland，尚未确认是固定模板或区域／行列映射。
- 当前数据来源是纸质课表，不对接学校教务系统，不需要图片识别。
- 不导入或执行参考档案中的自动化行动与提醒配置；不支持内容的提示方式见实现及验收建议。
- GT2 支持接收安卓端传入的课表及预设科目；不预设 BlueOS 能直接打开任意 Excel 文件。

### REQ-061 蓝牙与手动同步

- 用户手动触发同步，不做账号或云同步。
- 手表传输方向采用蓝牙，不依赖 Wi-Fi 或局域网。
- 支持安卓端向 GT2 导入；两端都可能产生本地修改，冲突时必须提示用户选择。
- 展示最后同步时间和尚未同步的修改。
- 具体同步方向、冲突选择粒度、安卓设备间传输、多设备状态记录尚未定稿。
- 数据同步的手动触发与自动校时是不同机制，不能混为一次自动上传课表的功能。

### REQ-062 离线与本地数据

核心管理和查看功能无需账号与互联网。保存后的数据应在重新打开应用后可用；未联网不能阻止已存课表的正常显示。

不要求分享给同学、订阅班级统一课表、独立备份恢复产品功能。为设备同步准备必要的导入／传输能力，不据此扩展为云平台。

## 8. 第一版排除项与发布

### REQ-070 明确排除

- 作业：曾提出，后明确移出第一版，相关编辑、同步、筛选及验收全部移除。
- 上下课提醒、声音、振动、主动弹窗和提醒配置。
- 自动化行动、插件、天气、账号、云服务与教务系统对接。
- 花哨动画、复杂外观配置和自由布局编辑器。
- 未要求的图片识别、课程笔记、考试倒计日、班级订阅或分享功能。

静默常驻通知和自动联网校时属于已确认需求，不受早期“不要常驻通知／联网”的表述排除。

### REQ-071 发布和阶段

- 项目名称保持“简单课表 / SimpleTimetable”。
- 开源发布安装包，不上架应用商店。
- 安卓优先；GT2 是后续平台目标，不将安卓模拟器通过等同于 GT2 已完成。
- 技术栈未指定，由实现阶段结合平台可行性选择。
- 尚未确定具体交付日期、最低手机 Android 版本或所有平台的发布时间。

## 9. 需求解释原则

1. 本文已确认条目是需求基线；用户后续明确修订优先。
2. 参考项目的技术实现不等于本项目必须使用相同框架或 UI。
3. 用户明确的移动端差异优先于 ClassIsland 的默认行为。
4. 未确认的细节列入待核实文档，不以建议填充为已确认需求。
5. 技术受限时报告实际限制与替代方案，不能静默取消进度条、GT2 独立编辑等必需能力。
