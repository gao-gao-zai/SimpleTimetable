# 第一版验收与测试计划

- 基线日期：2026-10-11
- 状态：验收计划，尚未执行；没有应用、构建或设备测试通过的声明
- 需求来源：[产品需求](requirements.md)

以下场景由已确认需求推导，用于开发阶段验收。表中列出的具体检查方法属于测试设计，不表示用户指定了某一种技术实现。待定阈值和平台能力必须先完成验证，再填写结果。

| ID | 关联需求 | 场景与操作 | 预期结果 |
| --- | --- | --- | --- |
| ACC-001 | REQ-020、062 | 在无网络、无账号状态下创建科目、时间表、课表，保存并重启应用 | 数据保留，能够继续编辑和查看 |
| ACC-002 | REQ-010～013 | 安卓手机／手表使用软键盘录入；GT2 选择内置或传入科目 | 安卓完整文字录入；GT2 不依赖文字键盘即可安排课程 |
| ACC-003 | REQ-013 | GT2 断开手机后修改上下课时间、轮换规则、课程安排、临时调课并保存 | 修改本地生效，重新打开后保留；涉及平台支持的项必须在 BlueOS 验证 |
| ACC-004 | REQ-021 | 构造不同星期、单双周及多周轮换档案，在日期边界切换 | 实际启用结果符合已核对的 ClassIsland 规则及明确记录的项目差异 |
| ACC-005 | REQ-022 | 当前启用 A，浏览／预览／编辑 B | 仅预览 B 不启用 B；保存修改按实际引用关系影响运行结果 |
| ACC-006 | REQ-023 | A、B 共用时间表 T；修改 T；另复制 T2 并关联 B | 共用时 A、B 同步受影响；改用 T2 后修改 T2 不改变 A 的作息 |
| ACC-007 | REQ-024 | 启用临时调课，结束应用进程后重开，再跨越有效期 | 到期前保留，到期后恢复正常规则；退出不提前清除 |
| ACC-008 | REQ-021、024 | 创建临时层、临时课表、课表群及预定安排 | 按核实后的优先级加载；临时修改不意外永久改写原课表 |
| ACC-009 | REQ-030、031 | 在上课开始、结束、课间结束前后检查显示 | 课程、上下课状态、倒计时、进度使用同一有效时间，不出现负倒计时或错误课程残留 |
| ACC-010 | REQ-030 | 当天无课、当天已结束、第一节前、课间四种状态 | 明确区分无课和已结束；有后续课程时显示下一节及距上课时间 |
| ACC-011 | REQ-030、031 | 两节课之间不创建显式课间条目 | 仍正确显示下一节和倒计时；进度按后续明确的区间规则验收 |
| ACC-012 | REQ-031 | 检查应用、通知、小组件、GT2 快捷卡片 | 每个要求的入口都有已过去比例进度条；不能用“只剩数字”判定通过 |
| ACC-013 | REQ-031 | 页面可见、切后台、熄屏，再重新进入 | 可见时按秒级目标更新；隐藏后停止页面秒级循环；恢复时重算而不是补跑遗漏次数 |
| ACC-014 | REQ-032 | 切换课程卡片、时间轴、周课表 | 三种浏览方式可用；手表周视图每页一天；浏览不改变实际启用状态 |
| ACC-015 | REQ-033、070 | 开启／关闭静默常驻通知，经过上下课时间点 | 通知可关闭；开启时展示课程、倒计时及进度；不响铃、不振动、不弹出主动提醒 |
| ACC-016 | REQ-050、051 | 切换时间来源、调整正负铃声偏移、联网校时后断网 | 状态和倒计时按同一有效时间重算；断网使用有效校时推算并显示状态 |
| ACC-017 | REQ-051 | 重启后无法可靠恢复软件时间 | 暂用系统时间并提示需要校时，不伪称仍为已精确校准状态 |
| ACC-018 | REQ-060 | 导入已声明支持的 ClassIsland、Excel／CSV 样例 | 科目、时间和课程关系与预期一致；实际支持格式必须有样例和兼容记录 |
| ACC-019 | REQ-060、070 | 导入含行动或提醒配置的档案 | 不执行行动，不启用提醒；不支持字段应明确说明，不能静默声称完全兼容 |
| ACC-020 | REQ-061 | 两端分别修改数据，再手动同步 | 冲突提示选择；展示同步时间与未同步修改，不静默丢弃本地编辑 |
| ACC-021 | REQ-061 | 中断蓝牙传输，随后重试 | 保持可用的完整本地数据，失败不显示为已同步；恢复后的结果可验证 |

导入失败不破坏已有数据、同步失败不留下半份数据、状态不误报，是实现阶段的数据完整性验收要求；具体事务或暂存机制不在本文预定。

## 3. 自动化与平台验证

用户同意使用 GitHub Actions 运行虚拟设备测试。进入实现阶段后，计划覆盖：

1. 课表解析、日期选择、轮换、临时覆盖、时间偏移等可独立验证的逻辑测试。
2. 安卓安装、启动、数据录入和重启恢复的流程测试。
3. 方屏、矩形手表屏、手机长屏及大字号的截图检查。
4. 支持格式的导入样例回归、异常文件与蓝牙协议层数据完整性检查。
5. 页面生命周期与时间跳变测试，检查不可见状态下的刷新行为。

该计划不表示已创建或运行 GitHub Actions 工作流。本次仅整理文档，不安装依赖、不触发 CI、不提交或推送。

### 验证边界

- 安卓模拟器可以检查安卓逻辑、布局和部分系统入口，不能证明杂牌手表厂商桌面一定支持小组件。
- 安卓模拟器不能作为 vivo WATCH GT2／BlueOS 的测试结果。
- 蓝牙真实互通、GT2 快捷卡片、厂商手势、读屏能力和续航需要相应平台验证。
- “页面只在可见时刷新”不等于零耗电；外部入口及校时的耗电另行测量，不预先给出续航保证。

## 4. 待验证指标

| 项目 | 当前目标或状态 |
| --- | --- |
| 应用内倒计时与进度 | 可见时每秒更新的设计目标，待实测 |
| 安卓通知／小组件数字 | 优先利用系统计时控件实现秒级倒计时，待设备兼容验证 |
| 安卓外部入口进度与课程切换 | 必须显示正确内容；允许的更新策略、实际延迟待验证 |
| GT2 应用和快捷卡片 | 应用以秒级为目标；卡片接口和频率尚未确认 |
| 蓝牙传输及冲突处理 | 用户可手动同步，失败保持完整数据；连接通道及合并粒度待确定 |
| 功耗、启动耗时、文件规模 | 尚未约定具体阈值，不能编造已达标结果 |

进入开发后，每个验收项应记录：版本／提交、平台与设备、输入样例、预期结果、实际结果及证据。未执行或平台受阻的项目应保留原状态，不能按通过处理。
